# Система аутентификации с нулевым разглашением (Fiat–Shamir)

Программная реализация прототипа системы аутентификации пользователей на основе
протокола с нулевым разглашением **Фиата–Шамира**, выполненная в рамках практики
и научной статьи «Разработка программной системы аутентификации пользователей на
основе протокола с нулевым разглашением Fiat-Shamir».

Система подтверждает личность пользователя **без передачи и хранения секрета на
стороне сервера**: на сервере хранится только открытый верификатор `v = s² mod n`,
по которому невозможно восстановить секрет `s`, но которого достаточно для проверки.

## Состав системы

| Компонент | Технологии | Роль | Каталог |
|-----------|-----------|------|---------|
| Бэкенд (проверяющий) | Python, FastAPI, SQLAlchemy | регистрация, проверка откликов, сессии | [`backend/`](backend/) |
| Клиент (доказывающий) | React, Vite, BigInt | генерация ключей, обязательства, отклики | [`client/`](client/) |
| Веб-интерфейс администратора | React, Vite | мониторинг пользователей, сессий, событий | [`admin/`](admin/) |
| База данных | MySQL (или SQLite) | учётные записи, верификаторы, журнал | — |

Логическая схема соответствует рисунку 1 статьи: React-клиент — доказывающий,
FastAPI-сервер — проверяющий, MySQL — хранилище, отдельная React-панель —
рабочее место администратора.

## Протокол Фиата–Шамира

Доверенный центр выбирает открытый модуль `n = p·q`. Доказывающий выбирает секрет
`s` и публикует верификатор `v = s² mod n`. В каждом из `t` раундов:

1. доказывающий выбирает случайное `r` и отправляет обязательство `x = r² mod n`;
2. проверяющий отвечает случайным бит-запросом `e ∈ {0, 1}`;
3. доказывающий возвращает отклик `y = r · sᵉ mod n`;
4. проверяющий принимает раунд, если `y² ≡ x · vᵉ (mod n)`.

Вероятность обмана в одном раунде — `1/2`, после `t` раундов — не более `2⁻ᵗ`.
Подробнее см. [`docs/protocol.md`](docs/protocol.md).

## Быстрый старт

### 1. Бэкенд

```bash
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# Запуск (по умолчанию используется SQLite в backend/instance/)
uvicorn app.main:app --reload --port 8000
```

Документация API (Swagger UI) доступна по адресу `http://localhost:8000/docs`.

#### Подключение MySQL (как в статье)

```bash
export ZEROFS_DATABASE_URL="mysql+pymysql://user:password@localhost:3306/zerofs"
uvicorn app.main:app --port 8000
```

### 2. Клиент-доказывающий

```bash
cd client
npm install
npm run dev          # http://localhost:5173
```

### 3. Панель администратора

```bash
cd admin
npm install
npm run dev          # http://localhost:5174
```

Логин по умолчанию — `admin` / `admin` (меняется переменными окружения).

В таблице сессий есть кнопка **«Подробнее»** — открывает пошаговый журнал раундов
выбранной сессии со всеми вычислениями (`x`, `e`, `y`) и проверкой равенства
`y² ≡ x·vᵉ (mod n)`.

### Проверка стойкости: вход без знания секрета

В клиенте есть флажок **«Войти как самозванец»** — вход выполняется с неверным
секретом (`s+1`). Такой вход **проваливается** на первом же раунде с запросом
`e = 1` (нужен настоящий секрет), что наглядно демонстрирует свойство корректности
протокола. То же делает `reference_prover.py` (попытка самозванца в демо).

### Демонстрация без браузера

Эталонный доказывающий на Python проходит полный сценарий (регистрация,
честный вход, попытка самозванца):

```bash
cd backend
python reference_prover.py --base-url http://localhost:8000/api demo alice
```

## Конфигурация (переменные окружения)

| Переменная | Назначение | По умолчанию |
|------------|-----------|--------------|
| `ZEROFS_DATABASE_URL` | строка подключения к БД | SQLite в `instance/` |
| `ZEROFS_MODULUS_BITS` | битовая длина модуля `n` | `512` |
| `ZEROFS_ROUNDS` | число раундов проверки | `20` |
| `ZEROFS_SESSION_TTL` | время жизни сессии, сек | `120` |
| `ZEROFS_ADMIN_USER` / `ZEROFS_ADMIN_PASSWORD` | учётные данные админа | `admin` / `admin` |
| `ZEROFS_MAX_FAILURES` | порог последовательных ошибок до блокировки | `3` |
| `ZEROFS_LOCKOUT_SECONDS` | длительность блокировки, сек | `300` |
| `ZEROFS_CORS_ORIGINS` | разрешённые источники CORS | localhost:5173/5174 |

## Тестирование

```bash
cd backend
pip install -r requirements.txt
pytest -q
```

Покрыты: модульная арифметика и тест простоты, корректность раунда для честного
доказывающего, отклонение самозванца, полный сценарий через REST API и доступ к
административным данным.

## Ограничения учебной реализации

Используются самописные модули модульной арифметики и криптографии, которые **не
являются сертифицированными средствами криптографической защиты информации**.
Интерактивный протокол требует защищённого канала связи (TLS) для предотвращения
атак повторного воспроизведения и «человек посередине», ограничения частоты
попыток, защиты секрета на клиенте и доверенной генерации модуля. Подробнее — в
заключительной части статьи и в [`docs/architecture.md`](docs/architecture.md).
